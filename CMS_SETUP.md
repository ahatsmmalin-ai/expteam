# Expert Team — подключение Decap CMS к GitHub и Cloudflare Pages

## Состояние и ограничения

Это **CMS-ready исходники**, не уже подключённая админка. В проекте уже есть структура редактируемого контента и серверная точка OAuth. Чтобы войти, владелец GitHub/Cloudflare должен создать OAuth-приложение, внести две переменные Cloudflare и проверить вход. Реальные фото, оригинальные благодарственные письма и формы CRM отсутствуют; CMS их не создаёт.

## 1. Что уже подготовлено

- 38 основных редактируемых страниц, 3 508 текстовых фрагментов в секциях;
- единое редактирование меню, подвала, кнопок и текста форм (content/global.json);
- SEO Title / Description каждой страницы;
- редактор реальных изображений команды, кейсов и писем (content/media.json);
- контакты и дополнительные ссылки меню;
- возможность создавать новые статьи и страницы, публикуемые Cloudflare;
- сохранены дизайн V8, 39 фирменных ассетов, существующие страницы и старые перенаправления;
- editorial workflow Decap CMS: черновик → проверка → публикация через GitHub;
- локальный статический просмотр отдельным архивом (не сама админка).

## 2. Загрузка в GitHub

Репозиторий: https://github.com/ahatsmmalin-ai/expteam, ветка **main**.

Распакуйте архив CMS_GITHUB_READY и загрузите **содержимое корня** в GitHub. Важнейшие папки: `templates/`, `content/`, `admin/`, `assets/`, `functions/`. Важнейшие файлы: `pages_build.py`, `requirements.txt`, `cms_pages_manifest.json`.

**Не удаляйте сразу исходные данные**, если в репозитории есть более свежие правки, которых нет в этом архиве: сначала сравните изменения. Сохраняйте резервную копию ветки main. После CMS-перехода не заменяйте `content/` старым ZIP от статических версий.

## 3. Cloudflare Pages

Проект: `expteam-staging`. Сборка должна оставаться:

- Framework preset: `None`
- Build command: `pip install -r requirements.txt && python pages_build.py`
- Build output directory: `dist`
- Root directory: пусто
- `PYTHON_VERSION` = `3.12`

Cloudflare автоматически обнаруживает функции в **корневой** папке `functions/` при Git-деплое. Они обрабатывают только `/api/*` (см. `_routes.json`). Временная переменная `EXPERTTEAM_INTERNAL_REVIEW` больше не используется в новой сборке.

После публикации должен открываться основной тестовый сайт: https://expteam-staging.pages.dev.

## 4. Создание GitHub OAuth App

Владелец репозитория в GitHub:

1. `Settings → Developer settings → OAuth Apps → New OAuth App`.
2. Application name: `Expert Team CMS — staging`.
3. Homepage URL: `https://expteam-staging.pages.dev`.
4. Authorization callback URL: `https://expteam-staging.pages.dev/api/callback`.
5. Зарегистрировать приложение и скопировать **Client ID**.
6. Нажать **Generate a new client secret** и сохранить Client Secret в секретном хранилище.

**Никогда не пересылайте Client Secret в чат и не загружайте его в GitHub.** Поскольку стандартная GitHub OAuth-схема Decap запрашивает scope `repo`, разрешайте доступ только доверенным сотрудникам. У пользователя CMS должны быть права записи в репозиторий.

## 5. Добавление секретов Cloudflare

В `Workers & Pages → expteam-staging → Settings → Variables and secrets` для окружения **Production**:

- `GITHUB_CLIENT_ID` — тип Text, значение из GitHub.
- `GITHUB_CLIENT_SECRET` — тип Secret, значение из GitHub.

Сохраните, затем выполните новый деплой. Эти переменные доступны Cloudflare Pages Functions на сервере; они не записаны в код или статический сайт.

## 6. Первый вход и проверка редактора

1. Откройте **https://expteam-staging.pages.dev/admin/**.
2. Нажмите вход через GitHub, подтвердите OAuth.
3. Откройте `01. Основные страницы → Главная`.
4. Измените один несущественный текст в секции. Сохраните **черновик**, просмотрите, затем опубликуйте через рабочий процесс.
5. Убедитесь, что CMS сохранила изменение в `content/pages/home.json` на GitHub.
6. Убедитесь, что новый Cloudflare Deployment стал успешным и обновление появилось на тестовой ссылке.
7. Верните тестовую формулировку обратно через CMS и снова опубликуйте.

**До реальной проверки OAuth нельзя считать админку полностью подключённой.**

## 7. Как пользоваться CMS

- `00. Общие настройки`: тексты меню, подвала и формы; реальные изображения; контакты.
- `01. Основные страницы`: главная, план, кейсы, блог, контакты и другие.
- `02. Наши решения`: три продукта и их тексты.
- `03. Кейсы`: девять подробных кейсов.
- `04. Статьи блога`: тексты десяти существующих статей.
- `05. Рубрики`: страницы рубрик.
- `07. Новые статьи`: создать новую статью с заголовком, URL, описанием, текстом Markdown и обложкой. После публикации карточка появится в каталоге блога.
- `08. Создать новую страницу`: Markdown-страница внутри `/stranicy/`. Для ссылки в меню укажите маршрут в «Дополнительные ссылки».

Ранее подготовленные блоки с цветными словами состоят из нескольких **редактируемых текстовых фрагментов** — не удаляйте пробелы между соседними фразами. Новые блоки и изменение расположения выполняются через HTML/CSS шаблоны, не через текстовые поля.

## 8. Работа через ИИ после подключения

Для визуальных правок изменяем `templates/`, `assets/style.css`, `assets/v4.css`, `assets/site.js` и при необходимости `pages_build.py`. **Не перезаписываем `content/` из старого ZIP.** Перед новой версией получаем актуальный ZIP/снимок репозитория, чтобы не потерять редактирование через CMS.

## 9. Важно до публичного запуска

- `robots.txt` и `X-Robots-Tag` пока запрещают индексацию (это staging).
- Заявки с форм пока не передаются в CRM, их нельзя проверять как рабочую воронку.
- Логотип/фото/письма/скриншоты — только оригинальные и с разрешением на публикацию.
- Если репозиторий публичный, **черновики в GitHub тоже могут быть доступны посторонним**, даже если сайт закрыт через Access или noindex.
- Подключение к production-домену `expertteam.pro` не выполнено.
