# Expert Team — корпоративная проверка до GitHub

**Версия:** 2026-11-02 · **Статус:** pre-GitHub / внутренний обзор. **Публичная публикация запрещена до согласования.**

Это полноценные исходники статического, SEO-ориентированного сайта на Python + Jinja2, а не один SPA-файл. Исходный HTML коммерческих страниц генерируется на этапе сборки, так что поисковые роботы смогут получить заголовки и контент из HTML после запуска.

### Быстрый просмотр (без установки программ)

Откройте отдельный файл `ExpertTeam_CORPORATE_PREVIEW.html` через Chrome. Он объединяет 35 маршрутов в один локальный макет, включая тестовую новую страницу `/stranicy/primer-cms/`. Локальный просмотр предназначен для демонстрации, а не для тестирования авторизации и сетевых форм.

### Сборка из исходников

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
python scripts/content_integrity.py
python build.py
python scripts/qa_check.py
python scripts/cms_smoke_test.py
```

`dist/` — результат сборки. Его нужно отдавать через HTTP-сервер с корректными маршрутами. `python build.py` выполняет только **тестовую** сборку: meta robots `noindex,nofollow`, в robots.txt `Disallow: /`, карта sitemap не содержит индексируемых страниц. `noindex` **не является защитой доступом** — корпоративный тестовый адрес должен быть закрыт паролем или SSO на хостинге.

### Управление материалами

Будущая CMS: **Decap CMS (GitHub backend)**, конфигурация `static/admin/config.yml`. Онлайн-авторизация ещё **не подключена**. Можно подготовить редактирование, не создавая репозиторий заранее, но тест реальных прав доступа и публикации придётся провести после создания GitHub-репозитория.

Через CMS можно будет редактировать:

* Главную: первый экран, FAQ, данные компании, контакты.
* Статические SEO Title/Description: главная, кейсы, о компании, цены, контакты, блог.
* Все 7 услуг: Title, Description, H1, этапы, блоки, цены, FAQ.
* Отдельные SEO-разделы услуг (H2 и текст).
* Цены и пакеты.
* Блог: новые статьи, обложки, авторов, alt, SEO-поля, тексты, внутренние ссылки.
* Кейсы: метрики, описание, доказательства и индивидуальные SEO-метаданные.
* **Новые страницы без редактирования кода** в безопасных URL-разделах `/stranicy/`, `/resheniya/`, `/materialy/`; собственные заголовки, текст, изображение и SEO-поля.

Большинство основных динамических материалов вынесено в `content/`. **Не всё содержимое сайта редактируется через CMS**: некоторые декоративные/структурные надписи на страницах (в том числе отдельные абзацы в шаблонах) пока фиксированы и потребуют отдельной задачи по переносу в поля. Это должно быть известно проверяющим.

### Структура

- `content/` — редактируемые JSON/Markdown-файлы.
- `content/pages/primer-cms.md` — тестовая новая страница (черновик, не попадает в production).
- `templates/` — Jinja2-шаблоны и UI сайта.
- `static/` — стили, JS, Decap CMS и WebP-обложки.
- `scripts/content_integrity.py` — данные/URL/редакционные ограничения.
- `scripts/qa_check.py` — маршрутная и базовая SEO-проверка после сборки.
- `scripts/cms_smoke_test.py` — симуляция работы CMS в изолированной временной папке.
- `.github/workflows/preflight.yml` — CI для будущего GitHub; **ничего не публикует**.
- `docs/CORPORATE_REVIEW.md` — чек-лист корпоративной приёмки.
- `docs/CMS_SETUP.md` — дальнейшее подключение CMS/авторизации.

### Перед созданием репозитория

1. Корпоративная команда проверяет дизайн, контент, 7 услуг, кейсы, цены, юридический блок, статьи и тестовую страницу.
2. Технический руководитель и SEO-специалист утверждают подход к редактированию и URL, в частности создание новых страниц.
3. Выбрать репозиторий и хостинг для **закрытого** тестового сайта.
4. После согласования создать **приватный** GitHub-репозиторий и загрузить **содержимое папки `site_source` в корень**. Без реальных токенов и паролей.
5. Настроить GitHub OAuth или Decap Turbo для редактора (доступы выдаются по ролям). Затем проверить цикл «редактировать → черновик → согласовать → собрать» уже на тестовом домене.
6. Настоящий production-релиз выполнять только после юридической, технической и SEO-проверок; он блокируется `build.py --production` до явных разрешений.

**Не загружайте в публичный доступ текущие неутверждённые статьи/кейсы:** даже при `noindex` они доступны посетителям с URL.
