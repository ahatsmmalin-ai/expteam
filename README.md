# EXPERT TEAM — полный редизайн 2026

Рабочая статическая многостраничная версия Expert Team, собранная по документу **«Комментарии по сайту»** и ZIP с **39 фирменными синими прозрачными элементами**.

## Что реализовано

- Визуальная система на белом фоне / чёрной типографике / фирменном синем `#0F09FF`. Наведение: `#0500DA`.
- Главная страница по 14 пунктам структуры: первый экран, проблемы, комплекс и операционка, цена, два продукта колл-центра, кейсы, письма, процесс, команда, FAQ, блог, маркетинговый план, подвал.
- 3 платных решения: `/resheniya/kompleksnyj-marketing/`, `/resheniya/leadstore-koll-centr/`, `/resheniya/reaktivaciya-bazy/`.
- Бесплатный маркетинговый план: `/marketingovyj-plan/`.
- Каталог кейсов с фильтрами, 9 карточек и страницы каждого кейса.
- Блог с **10 сохранёнными статьями** из предыдущей версии; они остаются **редакционными черновиками**.
- Сравнение «штатный маркетолог или команда», `/materialy/marketolog-ili-komanda/`.
- Интерактивный сценарный калькулятор `/kalkulyator-marketologa/`.
- 39 исходных элементов оптимизированы до WebP и включены в `static/assets/`.
- Redirects для 7 прежних страниц услуг + `/ceny/`, `/uslugi/`.
- CMS-ready JSON/Markdown и Decap-конфигурация. **Авторизация CMS пока НЕ подключена.**
- Staging noindex: `robots.txt`, meta robots; production release блокируется до разрешения.

## Как обновить текущий Cloudflare Pages

Репозиторий: `https://github.com/ahatsmmalin-ai/expteam`.
Проект: `expteam-staging`, `https://expteam-staging.pages.dev`.

1. **Сделайте резервную копию действующего GitHub-репозитория.**
2. **Распакуйте этот исходный ZIP**. В репозитории загрузите файлы и каталоги из папки архива **в корень**, сохранив их пути. ZIP как один файл загрузить недостаточно. Старые файлы `templates/*.html` или `content/services/*.json`, если остались, сборке нового сайта не мешают, но используются только архивно.
3. Убедитесь, что на вкладке Cloudflare Pages `Settings → Build` осталось:
   - build command: `pip install -r requirements.txt && python pages_build.py`
   - output: `dist`
   - root directory: пусто
   - `PYTHON_VERSION=3.12`
   - `EXPERTTEAM_INTERNAL_REVIEW=YES` — **только** если разрешена публичная ссылка на тестовую версию.
4. После push в `main` GitHub Actions выполняет QA, а Cloudflare автоматически пересоберёт staging.
5. Откройте тестовый адрес, проверьте мобильную версию, ссылки и калькулятор.

**Важно:** `*.pages.dev` публичен. Даже с `noindex` материалы доступны всем, кому известен адрес, а при публичном GitHub-репозитории — и через код. Не размещайте конфиденциальные данные.

## Как запустить локально

```bash
pip install -r requirements.txt
python build.py
python -m http.server 8000 --directory dist
```

Откройте http://localhost:8000/. Все страницы, CSS и изображения доступны через этот сервер.

## Быстрая проверка

```bash
python scripts/redesign_qa.py
python scripts/redesign_cms_smoke.py
EXPERTTEAM_INTERNAL_REVIEW=YES python pages_build.py
```

**Что именно проверяется:** ссылки и маршруты, цветовые ассеты, robots/noindex, 10 статей, страницы/фильтры, сценарий изменения JSON-данных и создание CMS-страницы, блокировка производственного релиза. Не проверяется вход через Decap OAuth или рабочая интеграция CRM, пока они не подключены.

## Контент для будущей CMS

- `content/redesign.json` — главный оффер, список компетенций и операционных задач, три решения и FAQ.
- `content/redesign_cases.json` — 9 кейсов и связанные изображения (поля `screenshots`, пока пусты).
- `content/letters.json` — список оригинальных благодарственных писем (поля `image`, `approved`).
- `content/team.json` — роли и будущие настоящие фотографии команды.
- `content/site.json` — адреса, Telegram, логотип (`logo_image`, пока пуст), контакты.
- `content/posts/*.md` — 10 старых SEO-статей.
- `content/pages/*.md` — дополнительные CMS-страницы.
- `static/admin/config.yml` — схема Decap CMS, **`cms_auth_ready: false` до настройки OAuth**.
