# CMS Expert Team — что готово и что нужно для подключения

Редактируемые файлы и Decap CMS настроены по новой структуре: три решения в `content/redesign.json`, 9 кейсов в `content/redesign_cases.json`, письма и реальные фото в `content/letters.json`, `content/team.json`, все статьи в `content/posts`.

Сайт развёрнут на Cloudflare Pages. **Cloudflare Pages не предоставляет GitHub OAuth для Decap CMS автоматически.** Поэтому `static/admin/config.yml` содержит `cms_auth_ready: false`, а `/admin/` показывает пояснение, не делает ложную попытку входа.

Для реального входа:
1. Утвердить список пользователей, которые смогут редактировать и публиковать данные.
2. Выбрать безопасный GitHub OAuth-proxy / поддерживаемый сервис, проверить хранение секретов и ограничение по пользователям.
3. Настроить GitHub OAuth App + HTTPS endpoints провайдера, не помещать OAuth secret в статические файлы.
4. Указать точный `base_url` и `auth_endpoint` при выбранной интеграции, проверить login/logout.
5. Только после этого поменять `cms_auth_ready: true` и пересобрать сайт.
6. Проверить полноценный сценарий: создать черновик, получить коммит/PR в GitHub, утвердить, перестроить Cloudflare Pages, проверить URL и откат.

Автоматические smoke-tests **не являются подтверждением работающего входа** в админку.
