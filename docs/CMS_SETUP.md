# Expert Team — подключение CMS (этап 3)

**Статус:** исходники CMS подготовлены, GitHub-репозиторий и вход сотрудников не подключены. Этот архив сам по себе не является запущенным онлайн-редактором. Утверждённый первый дизайн сайта не изменён.

## Самый простой путь после создания репозитория

1. Выбрать или создать приватный репозиторий GitHub и загрузить **содержимое папки проекта в корень** репозитория. Без этого CMS нечего редактировать. Не хранить в репозитории OAuth secrets и токены CRM.
2. Настроить безопасный способ входа в Decap CMS. Доступны две схемы:
   - **GitHub OAuth** (пользователям нужны права записи в репозиторий и настроенный OAuth provider): `python scripts/configure_cms.py --repo OWNER/REPO --auth-base-url https://AUTH.EXAMPLE.COM`. URL обработчика OAuth — отдельный рабочий серверный компонент, его нет в архиве.
   - **Decap Turbo** (отдельный сервис авторизации и проксирования GitHub): после создания сайта в Turbo взять его `turbo_site_id` и вызвать `python scripts/configure_cms.py --turbo-site-id UUID`. Условия сервиса нужно принять отдельно.
3. Подключить GitHub как источник сайта в Netlify либо другой статический хостинг. В **netlify.toml по умолчанию настроена безопасная тестовая сборка** `python build.py` и QA. Вывод — папка `dist`. Тестовый адрес может быть доступен любому, кто знает ссылку: `noindex` — не пароль, поэтому для приватного теста включите защиту доступа хостинга.
4. Проверить адрес `/admin/` на тестовом домене: вход, открытие услуги, создание черновика, pull request, согласование и запуск CI. У сотрудника должны быть соответствующие права в GitHub или Decap Turbo.
5. Сохраняйте изменения через **Editorial Workflow**: Draft → Review → Publish (merge pull request). Для SEO-статьи дополнительно нужен флаг `published: true`, иначе она не попадёт в production.
6. CMS хранит данные в `content/`, изображения в `static/uploads/`; сборка копирует их в `/assets/uploads/`.

## CMS-коллекции

- **Главная / Настройки**: данные компании, первый экран, формы, FAQ, прайс.
- **7 услуг**: Title, Description, H1, этапы, вопросы, связанные услуги.
- **SEO-разделы**: подробный текст страниц услуг.
- **SEO-блог**: рубрика, статья, автор, био, обложка, alt, дата, флаг публикации.
- **Кейсы**: результаты, ссылки на источники, подтверждение права публикации.

## Публичный релиз — только после согласования

Сейчас он **заблокирован**, и это сделано специально. До реального релиза нужны: утверждённая политика, проверенная CRM-передача заявок, подтверждённые кейсы и цены, информация о команде, SEO-редактура, проверка старых URL, домен и HTTPS.

- Проверка контента: `python scripts/content_integrity.py`.
- Готовность релиза: `python scripts/release_readiness.py`.
- В файл `content/release.json` ответственное лицо вручную вносит подтверждённые статусы, дату и имя проверяющего.
- При выпуске релиза: указать публичный HTTPS-адрес своего серверного приёмника заявок в переменной `EXPERTTEAM_FORM_ENDPOINT`, задать `EXPERTTEAM_GO_LIVE=YES` в закрытых настройках окружения CI/CD и сменить команду сборки с `python build.py` на `python build.py --production`.
- `--production` дополнительно блокируется до утверждения каждого кейса: `client_approved: true`, `evidence` с подтверждением. Это предотвращает случайную публикацию непроверенных результатов.

**Отправка заявок:** сайт посылает `POST` с JSON `{phone, consent, source}` только на специально настроенный HTTPS endpoint. Никаких токенов CRM в HTML нет. На стороне сервера необходимо настроить антиспам, лимиты, логирование без телефонов, согласия, защиту и подтверждение приёма. Без этого форма остаётся демонстрационной и ничего не отправляет.

## Что не является задачей одной CMS

- Защищённая серверная логика CRM и политика обработки персональных данных.
- Публикация настоящих фотографий команды, согласование кейсов и тарифов.
- Защита тестового адреса от посторонних и полноценная авторизация CMS.
- Регистрация Sitemap в Яндекс.Вебмастере / GSC, настройка Метрики, редиректы с Tilda.
- Месячная программа публикации статей и получение внешних ссылок.

**Источник для проверки способа авторизации:** https://decapcms.org/docs/github-backend/ ; https://decapcms.org/docs/turbo-connecting-a-site/ . **Не рекомендую строить новый проект на Netlify Git Gateway**: он помечен у Netlify как deprecated: https://docs.netlify.com/manage/security/secure-access-to-sites/git-gateway/ .
